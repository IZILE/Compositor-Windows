# 阶段 07a：快速操作不再跳回，窗口与桌面图标修正

## 用平实的话说明

之前的检查让动画先走一小步，再接受下一个操作。这次补上了更急的情况：鼠标还没等画面刷新，就从 A 移到 B 又回到 A。旧版在这种情况下会先露出 B，再退回 A，这正是“闪回”的一种可复现原因。

现在遇到这种操作，会先保持眼前的位置，取消已经放弃的目标，然后继续处理最新操作。左侧工具、标签、分段选项、顶层和下拉菜单都接入了这个处理。检查还发现按钮透明度、开关颜色、折叠高度也有同类问题，已一起修正。其他控件仍能继续动画，拖动数值保持即时响应。

标题栏图标的原因也找到了：旧路径把一张 256 像素 PNG 交给 Windows，小图标请求仍得到一个 256 像素的光标对象。新版改为真正的多尺寸 ICO，窗口会按需取得小图标。桌面图标主体在 48 像素画布中由约 40×39 放大至 44×44，保留原作渐变和阴影；16 像素帧留出安全边界。安装器会通知 Windows 图标和快捷方式已更新。

## 有什么证据

- 新增的同一帧内往返检查在修改前失败，修改后通过；开关颜色检查也先复现了失败，再修复。
- 90 个动画突发输入检查通过，覆盖中间帧、快速反向、同帧往返、返回中途坐标、共享样式和其他属性继续动画。
- 完整界面检查通过 2205 个断言，中英文布局及既有画布缓存、后台预览检查正常。
- 887 项核心测试通过，没有修改工程格式。
- 21 个窗口图标检查通过：直接检查 Windows 图标加载器得到的实际对象、16–64 像素尺寸、主体居中及边界。EXE／桌面快捷方式的最终安装验证正在进行。

## 还没有完成什么

这些检查能证明已覆盖的复现条件被修复，不能证明所有硬件、刷新率与 DPI 下都不会掉帧。当前没有 Mac 实机逐帧对照，也没有证据声称像素和时序完全一致。完整 Mac 功能仍有待移植项目，见[对齐记录](mac-parity-checklist.md)。本阶段没有删减解码器、字体或工程功能来缩小安装包。

下一步：验证最终 0.6.1 程序及安装器，覆盖原安装目录，发布源码、安装包与校验值到公开 GitHub 仓库。
